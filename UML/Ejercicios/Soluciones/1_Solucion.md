# Introducción a UML. Metodologías de Desarrollo - Solucionario

## Ejercicios resueltos

### Ejercicio tipo 1: Comprensión

#### Enunciado

Responde brevemente:

a) ¿Qué es UML?

b) ¿Por qué UML no se considera un lenguaje de programación?

c) ¿Qué ventajas aporta el uso de diagramas durante el desarrollo de software?

#### Solución

a) UML es un lenguaje gráfico utilizado para modelar y documentar sistemas software.

b) No es un lenguaje de programación porque no permite ejecutar instrucciones ni desarrollar aplicaciones directamente. Su objetivo es representar y diseñar sistemas.

c) Los diagramas facilitan la comunicación entre los participantes del proyecto, mejoran la comprensión del sistema y ayudan a detectar errores antes de programar.

---

### Ejercicio tipo 2: Identificación o clasificación

#### Enunciado

Indica si las siguientes afirmaciones corresponden a UML, Cascada o Agile.

#### Solución

1. Prioriza la respuesta al cambio → Agile

2. Es un lenguaje gráfico → UML

3. Divide el desarrollo en fases secuenciales → Cascada

4. Permite representar la estructura de un sistema → UML

5. Prioriza la colaboración con el cliente → Agile

Explicación:

- UML se utiliza para modelar.
- Cascada organiza el trabajo de forma secuencial.
- Agile favorece la adaptación y colaboración.

---

### Ejercicio tipo 3: Aplicación práctica

#### Enunciado

Aplicación para gestionar alumnos, cursos y matrículas.

#### Solución

Paso 1: Identificar los elementos del sistema.

- Alumno
- Curso
- Matrícula

Paso 2: Utilizar UML.

Se podrían crear diagramas de clases para representar las relaciones entre las entidades.

Paso 3: Beneficios.

- Comprensión del sistema.
- Detección temprana de errores.
- Mejor comunicación entre desarrolladores.

Paso 4: Elección de metodología.

Se recomienda Agile porque la academia puede solicitar cambios o nuevas funcionalidades durante el desarrollo.

---

### Ejercicio tipo 4: Análisis

#### Enunciado

Empresa con requisitos cambiantes.

#### Solución

La metodología más adecuada es Agile.

Razones:

1. Los requisitos cambian constantemente.
2. Agile permite adaptarse rápidamente.
3. El cliente participa activamente.
4. Se realizan entregas frecuentes.
5. Los cambios pueden incorporarse sin necesidad de reiniciar el proyecto.

Utilizar Cascada sería más complicado porque requiere una definición inicial estable de requisitos.

## Preguntas de reflexión (Respuestas orientativas)

### 1. ¿Puede desarrollarse software de calidad sin realizar modelado?

Es posible, pero aumenta significativamente el riesgo de errores, malentendidos y problemas de mantenimiento.

### 2. ¿Por qué UML sigue siendo útil aunque existan generadores automáticos de código?

Porque UML ayuda a analizar y comprender la solución antes de implementarla.

### 3. ¿En qué situaciones podría seguir siendo recomendable utilizar Cascada?

En proyectos con requisitos muy estables y bien definidos, como determinados sistemas industriales o administrativos.

### 4. ¿Qué riesgos puede tener Agile mal gestionado?

- Falta de planificación.
- Cambios constantes sin control.
- Dificultad para estimar costes.
- Retrasos en las entregas.

### 5. ¿Qué prioridad Agile consideras más importante?

Respuesta abierta. Una posible respuesta es la capacidad de adaptación al cambio, ya que permite ofrecer soluciones más alineadas con las necesidades reales del cliente.

## Resumen final

- UML es un lenguaje gráfico para modelar sistemas software.
- Fue creado por Grady Booch, James Rumbaugh e Ivar Jacobson.
- La OMG mantiene y estandariza UML.
- UML permite describir estructuras, comportamientos, modelos de datos y apoyar la generación de código.
- El modelo en cascada organiza el desarrollo en fases secuenciales.
- Agile propone una forma flexible de desarrollar software basada en colaboración, adaptación al cambio y entrega continua de valor.
- La elección de una metodología depende de las características y necesidades de cada proyecto.
