# Análisis y Especificación de Requisitos

## Objetivos de aprendizaje

Al finalizar este tema, el alumno será capaz de:

1. Identificar los distintos tipos de requisitos utilizados en proyectos software.
2. Comprender el uso de diagramas de flujo y diagramas de casos de uso para el análisis de requisitos.
3. Elaborar documentación básica de requisitos.
4. Aplicar técnicas básicas de validación de requisitos.
5. Comprender la importancia de la gestión de requisitos durante el ciclo de vida del software.

---

## Introducción teórica

El análisis y especificación de requisitos es una actividad fundamental dentro de la Ingeniería del Software. Su objetivo es comprender las necesidades de los usuarios y transformarlas en requisitos claros que sirvan como base para el desarrollo del sistema.

Un requisito describe una funcionalidad, restricción o necesidad que el software debe satisfacer. La calidad de los requisitos influye directamente en el éxito del proyecto.

### Tipos de requisitos

| Tipo de requisito | Descripción | Ejemplo |
|------------------|-------------|----------|
| Funcional | Describe lo que el sistema debe hacer. | El usuario podrá registrarse. |
| No funcional | Describe restricciones o atributos de calidad. | La aplicación responderá en menos de 2 segundos. |
| De negocio | Describe objetivos de la organización. | Incrementar las ventas online un 15%. |

### Modelos para el análisis de requisitos

#### Diagramas de flujo

Representan gráficamente un proceso y muestran actividades, decisiones y secuencias.

Ejemplo:

Inicio → Introducir datos → Validar → Resultado → Fin

#### Diagramas de casos de uso

Representan las funcionalidades del sistema desde el punto de vista de los usuarios.

Elementos principales:

- Actor
- Caso de uso
- Relaciones entre actores y funcionalidades

### Documentación de requisitos

La documentación recoge de forma estructurada los requisitos del sistema. Un requisito bien redactado debe ser:

- Claro
- Completo
- Consistente
- Verificable
- No ambiguo

### Validación de requisitos

La validación verifica que los requisitos reflejan correctamente las necesidades del cliente.

Algunas preguntas habituales son:

- ¿Es correcto?
- ¿Es comprensible?
- ¿Es verificable?
- ¿Existe alguna contradicción?

### Gestión de requisitos

Los requisitos pueden cambiar durante el proyecto. La gestión de requisitos permite:

- Controlar cambios.
- Mantener la trazabilidad.
- Gestionar versiones.
- Analizar impactos.

## Ejercicios

### Ejercicio 1: Comprensión

#### Enunciado

Responde brevemente:

1. ¿Qué es un requisito?
2. ¿Por qué es importante analizar correctamente los requisitos?
3. ¿Qué diferencia existe entre un requisito funcional y uno no funcional?

---

### Ejercicio 2: Clasificación de requisitos

#### Enunciado

Clasifica los siguientes requisitos como Funcional, No Funcional o De Negocio.

1. El usuario podrá reservar habitaciones online.
2. El sistema deberá estar disponible el 99,5 % del tiempo.
3. Incrementar un 20 % las reservas realizadas por Internet.
4. El cliente podrá cancelar una reserva.
5. La aplicación deberá responder en menos de 3 segundos.

---

### Ejercicio 3: Diagrama de flujo

#### Enunciado

Una aplicación de biblioteca sigue el siguiente proceso:

1. El usuario introduce su número de socio.
2. El sistema verifica si es válido.
3. Si es válido, permite realizar préstamos.
4. Si no es válido, muestra un mensaje de error.

Representa este proceso mediante un diagrama de flujo.

---

### Ejercicio 4: Casos de uso

#### Enunciado

En una plataforma de cursos online existen las siguientes funciones:

- Consultar catálogo de cursos.
- Inscribirse en un curso.
- Descargar certificados.

Identifica:

1. Los actores.
2. Los casos de uso.
3. Las relaciones entre ellos.

---

### Ejercicio 5: Documentación de requisitos

#### Enunciado

La empresa solicita lo siguiente:

"Los clientes deben poder consultar el historial de compras desde la aplicación móvil."

Redacta:

- Dos requisitos funcionales.
- Un requisito no funcional.

---

### Ejercicio 6: Validación de requisitos

#### Enunciado

Analiza los siguientes requisitos:

1. El sistema debe ser intuitivo.
2. El usuario podrá consultar sus pedidos.
3. La aplicación deberá ser rápida.

Indica:

- Cuáles presentan problemas.
- Qué problema tienen.
- Cómo podrían mejorarse.

---

### Ejercicio 7: Gestión de requisitos

#### Enunciado

Una tienda online solicita añadir un sistema de cupones de descuento cuando el desarrollo ya se encuentra avanzado.

Responde:

1. ¿Por qué debe gestionarse este cambio?
2. ¿Qué impacto podría tener?
3. ¿Qué artefactos del proyecto podrían verse afectados?

---

## Preguntas de reflexión

1. ¿Qué problemas pueden aparecer si los requisitos están mal definidos?
2. ¿Por qué es importante validar requisitos antes de comenzar a programar?
3. ¿Cómo ayudan los diagramas de casos de uso a comprender un sistema?
4. ¿Qué ventajas aporta mantener la trazabilidad de los requisitos?
5. ¿Cómo puede afectar un cambio de requisitos a la planificación del proyecto?

---

## Resumen del tema

El análisis y especificación de requisitos permite comprender qué necesita realmente el cliente y transformarlo en información útil para el equipo de desarrollo. Los requisitos pueden clasificarse en funcionales, no funcionales y de negocio. Para analizarlos se utilizan herramientas como los diagramas de flujo y los diagramas de casos de uso. Posteriormente, los requisitos deben documentarse, validarse y gestionarse para garantizar el éxito del proyecto.
